#+TITLE: Claude-in-tmux toolset — architecture

Implements the eight plans in [[../plans/][=plans/=]]. Those plans were written independently and collide in three places; this document is where the collisions are resolved. *Read this before editing any crate.*

Agents orient from [[file:atlas/index.org][=atlas/index.org=]] first; this document is the human deep-dive. Where the two disagree, that is a validity report for the atlas — the source code adjudicates, and the wrong side gets fixed.

** Collision 1 — four competing =pane-state.sh=

Four plans each specify their own hook script with the same name and different event vocabularies. There is one hook binary: *=cc-beacon=*.

| Claude Code event   | =cc-beacon= arg | effect                                                                          |
|----------------------+-------------------+----------------------------------------------------------------------------------|
| =SessionStart=       | =session-start=  | stamp =@claude_session_id=, rename window =cc:<dir>=, state → idle              |
| =UserPromptSubmit=   | =prompt=         | state → busy; on the first prompt only, stamp =@claude_task= slug               |
| =PreToolUse= =*=     | =activity=       | stamp =@claude_activity=, state → busy                                          |
| =PostToolUse= =*=    | =tool-done=      | append one ticker line to =/tmp/claude-progress/<pane>.log=                     |
| =Notification=       | =attn=           | state → needs-input; BEL to the pane tty *only if off-screen*                   |
| =Stop=               | =idle=           | state → idle, clear activity, write =── idle ──= ticker divider                 |
| =SessionEnd=         | =clear=          | unset all =@claude_*= pane options                                              |

Every branch exits 0 unconditionally. A hook that fails must never block an agent.

*Pane titles are never written.* The layout-resurrect plan wanted =select-pane -T <slug>=, but =talk ping= reads =#{pane_title}= to decide busy/idle — writing it would break inter-agent messaging for every plan at once. The slug lives in =@claude_task= and renders on the border instead.

** Collision 2 — six plans want =pane-border-format=

tmux has exactly one =pane-border-format= per window. All six border features compose into a single format string, applied once, in priority order:

#+begin_src text
▶ CLAUDE   pane_marked      to-claude inbox target
●REC       pane_pipe        cc-tape recording
[role]     @claude_role     talk-fleet role badge
󰄬 / 󰔟 /   @claude_state    cc-beacon lifecycle + @claude_activity (glyphs: tmuxlib State::glyph)
task-slug  @claude_task     cc-beacon first-prompt slug
#+end_src

Two ordering constraints, both load-bearing:

1. *The theme wins over plain =set -g=.* =tokyo-night.tmux:27= runs =set -g pane-border-status off=, and plugin =.tmux= files execute in the =run-shell= queue — /after/ the whole config file is parsed. A bare =set -g pane-border-status top= in =tmux.conf= is therefore overwritten. The beacon block must itself be a =run-shell=, placed after the TPM line, so it is queued later and lands last.
2. *Single-pane windows cost a row.* A =window-layout-changed= hook turns the border off for one-pane windows unless that pane is marked or recording.

=tmux-ace-window= saves and restores =pane-border-status=/=-format= at the /window/ level around a jump (=helpers.sh:24-37=); the beacon sets them globally, so =prefix o= leaves the format intact.

** Collision 3 — =talk= is bash, the goal says Rust

=talk='s existing primitives (=send_text=, =ping=, =read-since=) are proven and stay untouched. *=talk-fleet=* is a separate Rust binary that adds role addressing and fan-out on top, shelling out to =talk= for delivery. The only edit to the bash =talk= is one line in its target resolution, so =@role= works in =talk send= too.

** Crates

Every crate below is Rust in the =tools/= cargo workspace *except =sift=,
=pane-jump= and =cc-main-menu=*. =sift= and =pane-jump= are C++ built by cmake
(user directive for sift, 2026-08-27; pane-jump followed it). =cc-main-menu= is
C++20 + FTXUI built by *Meson* (user directive in its own spec, 2026-11-11 —
the cmake directive was sift's, not a rule for every C++ tool); FTXUI is a
CMake project pulled in through Meson's cmake module. Each divergence is a user
directive, not a technical finding; the cost is now three build systems in the
bootstrap, contained the same way each time — every binary lands in
=target/release/= next to the cargo output, so =claude.conf= keeps one path shape
for every tool. One command builds all of them, which is also the recovery after
=cargo clean= (it deletes the cmake and meson binaries too):

#+begin_src sh
bash ~/.tmux/tools/build-all.sh     # cargo, then sift, pane-jump (cmake), then cc-main-menu (meson)
#+end_src

The individual steps, as =build-all.sh= runs them:

#+begin_src sh
cd ~/.tmux/tools
cargo build --release
cmake -S sift -B target/cmake-build -DCMAKE_BUILD_TYPE=Release && cmake --build target/cmake-build
cmake -S pane-jump -B target/cmake-build-pane-jump -DCMAKE_BUILD_TYPE=Release && cmake --build target/cmake-build-pane-jump
bash cc-main-menu/scripts/build.sh  # meson + ninja; first configure clones FTXUI (network)
#+end_src

=sift= has no =tmuxlib=. The only pieces it had to re-implement on the C++ side
are the =tmux= subprocess call and the literal-message helper; it spawns =tmux=
through =execvp= with an argv vector, never a shell string.

** Per-pane option contract

Owned by =cc-beacon= unless noted. Consumers must tolerate every one being empty — a Claude started before the hooks were wired stamps nothing, which is why [[tmuxlib/src/lib.rs][=Pane::state=]] falls back to the pane-title heuristic.

| option                | values                            | written by | read by                                  |
|-------------------------+-------------------------------------+-------------+---------------------------------------------|
| =@claude_state=       | =busy= =idle= =needs-input=       | cc-beacon  | cc-attend, cc-fleet, talk-fleet, border  |
| =@claude_since=       | epoch seconds                     | cc-beacon  | cc-attend (oldest-blocked wins), cc-fleet |
| =@claude_activity=    | ≤48 chars, format-sanitized       | cc-beacon  | border, cc-fleet                         |
| =@claude_task=        | kebab slug of first prompt        | cc-beacon  | border, cc-layout                        |
| =@claude_session_id=  | UUID                               | cc-beacon  | cc-layout (=claude --resume=)            |
| =@claude_role=        | role name                          | talk-fleet | border, talk-fleet                       |

There is deliberately *no* per-window rollup option. tmux computes it live: =#{P:}= loops a window's panes and =#{W:}= loops a session's windows, so the status bar derives "does this window hold a blocked agent" straight from =@claude_state=. =cc-beacon install-bar= publishes that per-window rollup as the global format option =@claude_tab_glyph=, which tmux.conf's =@catppuccin_window_*_text= embeds with =#{E:}= so the glyph sits inside the tab block; the fleet roster is appended to =status-right= over the cached theme value =@claude_bar_base_sr=. Storing it would cost two extra tmux round-trips on every tool call and could go stale when a pane moved between windows.

One trap worth knowing before editing those formats: *=#{P:A,B}= takes two formats* — =A= for the active pane, =B= for the others — so the same format must be written twice to visit every pane. =#{P:#{@claude_state},}= looks right and silently reports one pane, which hides exactly the case the glyphs exist for (a blocked agent behind an active sibling). Measured on this machine: batching the beacon's writes into one tmux invocation and dropping the stored rollup took the per-tool-call hook from 21 ms to 4 ms.

Anything derived from tool arguments passes through =sanitize_format()= before being stamped: an activity string of =echo #{pane_pid}= must render literally, not expand.

*That mandate covers text entering a /format context/* — a pane option, a border format, a =display-message= without =-l=. It is not the only way to be safe. =seek= echoes raw pane text back to the status line and deliberately does /not/ sanitize it: it stamps no options and passes =-l= on every message, so there is no format context to escape from, and filtering would corrupt the text the user asked to copy. =sift= takes the same route for the same reason, and renders pane text only into its own popup. The rule for a new tool is therefore: *either* keep untrusted text out of every format context (and prove it, as =seek= does), *or* sanitize. Note =tmuxlib::message()= expands formats — use [[tmuxlib/src/lib.rs][=message_literal()=]] for anything derived from pane text.

** Conventions for every binary here

- *Exit 0 when there is nothing to do.* These run from key bindings and hooks; a non-zero exit surfaces as a tmux error popup or a blocked agent.
- *Never write pane titles* (see Collision 1).
- *Report the resolved target.* Anything that delivers text elsewhere calls =tmux display-message= so a mis-send is visible rather than silent.
- *No =git add= of anything but explicit paths*, per the home repo's CLAUDE.md.
