* Summary

=win-order= is the popup window reorderer bound to =prefix A=: it lists the windows of the current session, lets the user carry one up or down with =J= / =K=, and on Enter turns the new order into a batch of =swap-window= calls. It exists so that reordering tabs never needs =swap-window -s 0 -t 1= typed from memory — the footer names every key, and nothing reaches tmux until Enter, so Esc is a guaranteed no-op. It is the workspace's first Rust tool that draws its own TUI (ratatui with the crossterm backend); sift and pane-jump own their keystroke loops in C++, cc-fleet hands its list to fzf. The session comes from =display-message -p '#{session_id}'= because display-popup does not expand formats in its shell command, and every swap target is a =session:index= address, so the batch does not depend on which session the popup's own tmux client resolves to. Window names are only rendered into the popup, after =sanitize_format=; no option is stamped and errors go through =message_literal=.

* Crux

The order is applied over the session's *existing* index set — gaps and =base-index= survive — by filling slot 0, then slot 1, and so on, one swap per slot that holds the wrong window; an unchanged order emits nothing:

#+begin_src rust :file win-order/src/main.rs :lines 60-85
/// The `swap-window` commands that turn `current` into `desired`.
///
/// `slots` is the session's index set in ascending order; `current[i]` and
/// `desired[i]` are the window ids that occupy / should occupy `slots[i]`.
/// Selection-sort shape: fill slot 0, then slot 1, … — at most `n - 1` swaps,
/// none when nothing moved. Targets are `session:index`, so the batch never
/// depends on which session the popup's own tmux client resolves to.
fn plan_swaps(session: &str, slots: &[u32], current: &[String], desired: &[String]) -> Vec<Vec<String>> {
    let mut cur = current.to_vec();
    let mut cmds = Vec::new();
    for i in 0..cur.len() {
        if cur[i] == desired[i] {
            continue;
        }
        let Some(j) = cur.iter().position(|id| *id == desired[i]) else { continue };
        cmds.push(vec![
            "swap-window".to_string(),
            "-d".to_string(),
            "-s".to_string(),
            format!("{session}:{}", slots[j]),
            "-t".to_string(),
            format!("{session}:{}", slots[i]),
        ]);
        cur.swap(i, j);
    }
    cmds
#+end_src

After the swaps, =run()= appends =select-window -t <id>= of the window that was current when the popup opened (=main.rs:131-133=), so the user's focus follows the window, not the index. =-d= on each swap keeps tmux from moving focus mid-batch. The whole batch is one =tmuxlib::tmux_batch= call; a failure is reported on the status line as possibly partial.
