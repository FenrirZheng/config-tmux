* Summary

Every Claude Code session's lifecycle — working, waiting for input, blocked on a permission prompt — is represented as a small set of tmux pane user options (=@claude_state=, =@claude_since=, =@claude_activity=, =@claude_task=, =@claude_session_id=, =@claude_role=) rather than as a file or a daemon: tmux itself is the shared, always-live store, and any binary reads a pane's state with one =show-options -p= call. cc-beacon is the sole writer, mapping each of the 7 hook events to a State transition defined once in tmuxlib; all consumers (cc-attend's "jump to neediest pane", cc-fleet's picker rows, talk-fleet's state-aware fan-out, the status-bar glyphs) parse the same option through the same =State::parse= / =priority()= logic, so ordering — "blocked wins" — is defined in exactly one place. There is deliberately no stored per-window or per-fleet rollup: tmux's own =#{P:}= / =#{W:}= format loops compute "does this window hold a blocked agent" live from per-pane options on every status refresh, which dropped hot-path hook latency from 21ms to 4ms versus the earlier stored-rollup design (ARCHITECTURE.org). Panes that predate the hooks fall back to a pane-title glyph heuristic instead of reporting Unknown. The protocol's defensive half: anything written into these options first passes =sanitize_format()=, because the values are later substituted into tmux format strings where raw =#{...}= would be re-expanded.

* Crux

The state vocabulary, defined once for every writer and reader:

#+begin_src rust :file tmuxlib/src/lib.rs :lines 40-50
pub enum State {
    /// Blocked on a permission prompt or otherwise waiting for a human.
    NeedsInput,
    /// Turn finished; the agent is waiting for its next prompt.
    Idle,
    /// Working.
    Busy,
    /// Not a Claude pane, or no beacon has been stamped yet.
    Unknown,
}
#+end_src

The event → state-write table, quoted from the architecture doc:

#+begin_quote :file ARCHITECTURE.org :lines 23-31
| Claude Code event   | =cc-beacon= arg | effect                                                                          |
|----------------------+-------------------+----------------------------------------------------------------------------------|
| =SessionStart=       | =session-start=  | stamp =@claude_session_id=, rename window =cc:<dir>=, state → idle              |
| =UserPromptSubmit=   | =prompt=         | state → busy; on the first prompt only, stamp =@claude_task= slug               |
| =PreToolUse= =*=     | =activity=       | stamp =@claude_activity=, state → busy                                          |
| =PostToolUse= =*=    | =tool-done=      | append one ticker line to =/tmp/claude-progress/<pane>.log=                     |
| =Notification=       | =attn=           | state → needs-input; BEL to the pane tty *only if off-screen*                   |
| =Stop=               | =idle=           | state → idle, clear activity, write =── idle ──= ticker divider                 |
| =SessionEnd=         | =clear=          | unset all =@claude_*= pane options                                              |
#+end_quote

The window rollup is computed live from the option by tmux, never stored; =install-bar= publishes it as =@claude_tab_glyph= (and a colourless twin =@claude_tab_glyph_mono= for the current tab's filled block), glyphs from =State::glyph()=:

#+begin_src rust :file cc-beacon/src/main.rs :lines 217-229
fn window_glyph() -> String {
    let (n, b, i) = (
        t::State::NeedsInput.glyph(),
        t::State::Busy.glyph(),
        t::State::Idle.glyph(),
    );
    format!(
        "#{{?{},#[fg=#f38ba8]#[bold] {n},#{{?{},#[fg=#f9e2af] {b},#{{?{},#[fg=#a6e3a1] {i},}}}}}}#[nobold]",
        any_pane("needs-input"),
        any_pane("busy"),
        any_pane("idle"),
    )
}
#+end_src
