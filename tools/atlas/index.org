* How to use this atlas

Read the node before the source: each node explains one part of this workspace in prose, quotes the lines that carry the logic, and names its exact source files. Follow the typed links between nodes instead of re-deriving structure by grepping. The atlas covers understanding, not every file — the Coverage section below says what it does not claim to explain; grep the repo for that. With the atlas-nav skill installed, follow its discipline (it verifies node freshness once per session); without it, treat nodes as helpful but unverified — where a node and the source disagree, the source wins. [[file:../ARCHITECTURE.org][ARCHITECTURE.org]] is the human deep-dive companion; a disagreement between it and the atlas is a validity report, adjudicated by the source.

* Coverage

11 nodes over 30 source files (31 unique Sources paths, counted 2026-11-11 with =grep -hoE '^:[^:]+: sha256' atlas/*.org | sort -u=) — every crate in the workspace is covered by some node, plus the three non-Rust tools (=sift= and =pane-jump=, C++ under cmake, and =cc-main-menu=, C++ + FTXUI under Meson). The one path that is not a source file is =ARCHITECTURE.org=, a document this atlas draws on, not a source it explains. Deliberately not explained: per-crate internals beyond each crux (cc-tape's strip mode, cc-launch's project/pair flows, cc-layout's TSV escaping, sift's terminal/rendering layer — its raw-mode setup, key decoding and popup drawing are ordinary TUI plumbing, unlike the tmux arithmetic its node does cover, and pane-jump's copy of that same layer for the same reason, and cc-main-menu's FTXUI component tree and fuzzy scoring constants in =ui.cpp= / =fuzzy_filter.cpp=, which are hashed but not explained), the bash =talk= primitives themselves (they live outside this workspace, in =~/.tmux=), and the build systems. Leaf subsystems (cc-main-menu, pane-jump, session-lifecycle, talk-fleet, win-order) have no inbound edges by design — nothing in the workspace depends on them; the link checker reports them as orphans, which is accepted and expected for a star-shaped codebase.
