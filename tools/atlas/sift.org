* Summary

=sift= is the popup regex search bound to =prefix /=, and the one thing in =tools/= that is not Rust: it is C++ built by cmake, which writes its binary into =target/release/= beside the cargo output so =claude.conf= keeps one path shape for every tool. It exists because tmux's incremental search is plain-text only, so the previous binding made you type a regex blind into a =command-prompt= and learn only on Enter whether it matched; =sift= owns the keystroke loop instead and lists every occurrence in the scrollback as you type. That is a deliberate narrowing of ADR-0001's "don't own the interaction loop" rule to plain search only — see ADR-0005.

What it pointedly does *not* own is the jump. On Enter it seats the copy-mode cursor just past the chosen occurrence and then issues tmux's own =search-backward= with the same pattern, so *tmux* ends up holding the search and match highlighting, =n= / =N=, and seek's =w= / =W= / =l= / =L= grab keys all keep working unchanged. Almost every tmux command in that sequence misbehaves relative to its name — =goto-line= sets a scroll offset rather than a line number, and both searches wrap silently when they miss — so the jump ends by re-reading the cursor's coordinates and asserting where it landed rather than trusting the commands. The measured surprises are recorded in the source comments and in ADR-0005's Notes.

A popup cannot be *told* which pane it belongs to, which is why =sift= takes no pane argument from its binding. =display-popup= does not format-expand its shell-command (nor its =-e=), so a binding passing =#{pane_id}= hands over those literal characters; and =$TMUX_PANE= inside a popup names the popup's own pseudo-pane, so it would search the wrong thing instead of failing. =origin_pane()= asks tmux for the client's active pane instead — the one the key was pressed in. Getting this wrong is invisible in a pane-based test: it shows up only as a popup that flashes and shuts.

The C++ is C++20 and dependency-free, and holds itself to a shape worth knowing before opening the file: every OS resource — the tmux pipe, the compiled regex, the terminal's raw mode — is owned by an RAII type (=Fd=, =Regex=, =RawMode=), so no exit path releases anything by hand and there is no =atexit=; fallible lookups return =std::optional= rather than taking a =bool* ok=; reader parameters are =std::string_view=; and the UTF-8 decoder is =constexpr= and carries its own unit tests as =static_assert=, so the byte/character/cell confusion this tool exists to avoid fails the *build* rather than the pane. The tmux command list is assembled by a concept-constrained variadic =chain()= that owns the =;= separator. =CMakeLists.txt= holds the source to =-Wconversion -Wsign-conversion -Wold-style-cast -Wshadow= on top of =-Wall -Wextra -Wpedantic=, and the =asan= preset builds an ASan+UBSan twin named =sift-asan= — a different name on purpose, because it shares =target/release/= with the binary =prefix /= runs. Both builds go through =CMakePresets.json= (=cmake --preset release= / =--preset asan=), which pins the Ninja generator and the build directory. Ninja is chosen for the no-op rebuild (16 ms against make's 56 ms), not for compile speed: one translation unit gives a build scheduler nothing to parallelise, and a full build measures the same either way.

ADR-0007 gave the keystroke loop its first mode: left =Alt-<digit>= claims a match by its ordinal in the result list instead of walking arrows O(N) times. The entry key was free to claim because those bytes were already being decoded and discarded — =read_key()='s =ESC= branch fell through to =Key::None= for any byte that wasn't =[= or =O=, so teaching it =Alt-<digit>= added a case, not a new read. The whole mode lives in one field, =Ui::goto_buf=: non-empty *is* ordinal mode, so there is no separate flag that could drift out of sync with it. Buffer and selection are kept as one object — every digit narrows =u.sel= immediately (=push_ordinal_digit=), and every key that moves the selection rewrites the buffer from it (=sync_ordinal=) — so =Enter= confirms an ordinal already on screen rather than wagering on one that might not exist, and there is no "no such match" error path to write. =draw()= grew a cyan ordinal column that renders always, at the width of the current /N/, left of the still-dim line-number column, and it now swaps its live prompt between =regex>= and =goto>= so the mode is never invisible. That prompt swap is also why =draw()= grew a footer-width guard: the function is contracted to emit exactly =h= lines, so a footer one cell over the pane width wraps, scrolls the pane, and carries the header — the =goto>= prompt included — off the top of the screen. =utf8_fit()= is the forward inverse of =utf8_cells()=, cutting the footer string on a character boundary rather than a byte one.

There is no =tmuxlib= on this side. The only pieces re-implemented in C++ are the =execvp=-based tmux spawn (an argv vector, never a shell string) and the literal =-l= message helper — which together are how =sift= discharges the same format-context proof obligation =seek= does: it stamps no pane options and renders pane text only into its own popup, so there is no format context to escape from and nothing has to be filtered. =sift rows <pane> <regex>= is the headless seam, mirroring =cc-fleet rows=; the behaviour above is pinned by =records/2026-08-27-2240-tmux-sift/assets/scripts/verify-sift-jump.sh= (13 assertions, including the jump arithmetic over CJK) and =verify-sift-live.sh= (19 assertions over real keystrokes, the last driving the shipped binding itself) — those are what redden if the sequence shifts.

* Crux

The tab-splitting that used to be inlined here — and again, differently, in =pane_geom()= — is now one =parse_fields<N>= reading with =std::from_chars=. Same three-line landing test, one parser:

#+begin_src cpp :file sift/src/main.cpp :lines 220-231
template <size_t N>
std::array<long, N> parse_fields(std::string_view s) {
    std::array<long, N> out{};
    for (size_t i = 0; i < N; ++i) {
        const size_t     tab   = s.find('\t');
        std::string_view field = s.substr(0, tab);
        std::from_chars(field.data(), field.data() + field.size(), out[i]);
        if (tab == std::string_view::npos) break;
        s.remove_prefix(tab + 1);
    }
    return out;
}
