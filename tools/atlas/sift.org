* Summary

=sift= is the popup regex search bound to =prefix /=: a Rust crate in the =tools/= cargo workspace like every other tool here, since a 2026-08-31 port from C++/cmake (ADR-0006). It exists because tmux's incremental search is plain-text only, so the previous binding made you type a regex blind into a =command-prompt= and learn only on Enter whether it matched; =sift= owns the keystroke loop instead and lists every occurrence in the scrollback as you type. That is a deliberate narrowing of ADR-0001's "don't own the interaction loop" rule to plain search only — see ADR-0005.

What it pointedly does *not* own is the jump. On Enter it seats the copy-mode cursor just past the chosen occurrence and then issues tmux's own =search-backward= with the same pattern, so *tmux* ends up holding the search and match highlighting, =n= / =N=, and seek's =w= / =W= / =l= / =L= grab keys all keep working unchanged. Almost every tmux command in that sequence misbehaves relative to its name — =goto-line= sets a scroll offset rather than a line number, and both searches wrap silently when they miss — so the jump ends by re-reading the cursor's coordinates and asserting where it landed rather than trusting the commands. The measured surprises are recorded in the source comments and in ADR-0005's Notes.

A popup cannot be *told* which pane it belongs to, which is why =sift= takes no pane argument from its binding. =display-popup= does not format-expand its shell-command (nor its =-e=), so a binding passing =#{pane_id}= hands over those literal characters; and =$TMUX_PANE= inside a popup names the popup's own pseudo-pane, so it would search the wrong thing instead of failing. =origin_pane()= asks tmux for the client's active pane instead — the one the key was pressed in. Getting this wrong is invisible in a pane-based test: it shows up only as a popup that flashes and shuts.

There is no =tmuxlib= on this side. The only pieces re-implemented are the =std::process::Command=-based tmux spawn (an argv vector, never a shell string) and the literal =-l= message helper — which together are how =sift= discharges the same format-context proof obligation =seek= does: it stamps no pane options and renders pane text only into its own popup, so there is no format context to escape from and nothing has to be filtered. Its regex engine is glibc =regcomp=/=regexec= (=REG_EXTENDED=) reached through raw =libc= FFI rather than the =regex= crate — ADR-0006's reasoning is dialect fidelity: tmux performs the actual jump via its own POSIX-ERE =search-backward=, so sift's candidate list has to come from the identical engine, matching leftmost-longest semantics, backreferences and =\<=/=\>=, and reading =\d= as a literal =d=, or the two can disagree after a jump. =sift rows <pane> <regex>= is the headless seam, mirroring =cc-fleet rows=; the behaviour above is pinned by =records/2026-08-27-2240-tmux-sift/assets/scripts/verify-sift-jump.sh= (13 assertions, including the jump arithmetic over CJK — measured unchanged across the Rust port) and =verify-sift-live.sh= (6 assertions over real keystrokes, the last driving the shipped binding itself) — those are what redden if the sequence shifts.

* Crux

=goto-line= is a scroll offset from the bottom of the history, not a line number, so the cursor row has to be pinned with =history-top= first; only then is =history_size - line= an exact seek. =history_size= is re-read here rather than reused from the capture, because it moves while the pane keeps printing:
