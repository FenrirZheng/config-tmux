* Summary

=pane-jump= is the popup pane picker bound to =prefix g=: it lists every pane on the server, narrows the list on =#{pane_title}= as you type, and hands tmux one =switch-client= when you press Enter. It answers "take me to the pane called X" for *any* pane, which nothing else here does — cc-fleet's picker lists Claude panes only, ace-window is positional, and tmux's own =choose-tree -f= opens with the cursor on the session row and *ignores a filter that would leave the list empty*, so a typo showed the whole tree and a blind Enter moved nothing (both faults measured in runbooks/switch-pane-by-name.md). The whole tool is four steps: one =list-panes -a -F= call builds the rows, every keystroke folds the query and the titles to lowercase code points, a substring test picks the rows to show, and Enter runs =switch-client -t <pane_id>=, which is enough on its own because tmux treats a pane target as a complete address and changes session, window and pane in one call. Only the *title* column is matched — location and command are rendered as dim context, so typing =bash= selects nothing rather than every shell — the query is a plain string and not a regex, as the =#{mi:*x*,…}= filter it replaced was, and the selection returns to the first row on every query change, so a fragment that narrows the list to one pane needs no arrow key before Enter. Titles are read and never written, because cc-attend, cc-fleet and =talk ping= classify a pane from =#{pane_title}= when no =@claude_state= is stamped, and they are untrusted text, so tmux is spawned only through =execvp= with an argv vector, no pane option is ever stamped, and the file's single =display-message= helper is literal (=-l=). Three entry points keep both halves testable without a TUI — =pane-jump= (the bound popup), =pane-jump rows [fragment]= (one tab-separated line per pane: id, location, command, title), =pane-jump jump <pane_id>= (the guarded switch) — and =verify-pane-jump.sh= pins all of it with 28 assertions, five groups over those seams and three driving the shipped binding with real keystrokes.

* Crux

Rows come from one tmux call whose format string is a compile-time constant, and the scope =-a= is the whole server — every pane, every session, which is what the replaced binding covered:

#+begin_src cpp :file pane-jump/src/main.cpp :lines 295-299
// One tmux call, argv vector, never a shell string. Scope is `-a`: every pane on
// the server, in every session, which is the scope the replaced binding had.
constexpr std::string_view kRowFormat =
    "#{pane_id}\t#{session_name}:#{window_index}.#{pane_index}\t"
    "#{pane_current_command}\t#{pane_title}";
#+end_src

The match is the middle of the chain: both sides are decoded to code points and folded with =towlower= under the user's locale, then compared as sequences. ASCII behaves exactly as tmux's =#{mi:}= did; for non-ASCII the fold is best effort and agreement with =mi= is [未驗證]. The empty needle matching everything is what makes the list open complete and narrow as characters arrive:

#+begin_src cpp :file pane-jump/src/main.cpp :lines 348-362
[[nodiscard]] std::u32string fold(std::string_view s) {
    std::u32string out;
    for (size_t i = 0; i < s.size();) {
        const auto d = utf8_decode(s, i);
        out.push_back(static_cast<char32_t>(towlower(static_cast<wint_t>(d.cp))));
        i += static_cast<size_t>(d.len);
    }
    return out;
}

// An empty needle matches every row: the list opens complete (R1) and narrows
// as characters arrive.
[[nodiscard]] bool title_matches(const Row& r, const std::u32string& needle) {
    return fold(r.title).find(needle) != std::u32string::npos;
}
#+end_src

Enter is where the two failure modes are decided. On zero rows it sets a notice and breaks back into the loop instead of returning: the popup stays open so the query can be corrected, and the alternative — closing, or falling back to the full list — is exactly the =choose-tree= behaviour the tool exists to replace. On a real row the terminal is restored *before* the client is switched, because after the switch this popup's client is looking at another pane:

#+begin_src cpp :file pane-jump/src/main.cpp :lines 680-693
            case Key::Enter: {
                if (u.shown.empty()) {
                    // Fail closed (R4): no full list, no silent success, and the
                    // popup stays open so the query can be corrected.
                    u.notice = "pane-jump: no pane title matches";
                    break;
                }
                const std::string id = u.rows[u.shown[u.sel]].id;
                term.restore();               // before the client moves elsewhere
                // A failed switch-client would otherwise be a silent no-op: the
                // popup is already gone and the client is still where it was.
                if (!jump(id)) say(std::format("pane-jump: switch-client failed for {}", id));
                return 0;
            }
#+end_src

=jump()= itself is eight lines (=main.cpp:647-654=) and exists for its guard: =tmux switch-client -t ""= exits 0 and moves nothing, so an empty id would be a silent success. It is refused and reported instead, on stderr for the =jump= seam and on the status line for a human. Its =bool= is read by both callers: a =switch-client= that fails on a live id is reported too, by =run_ui= on the status line (the popup is already gone) and by =run_jump= on both.

Every path returns 0 — the miss, the empty id, a failed switch, the usage error (=main.cpp:774=, =main.cpp:788=). A non-zero exit from a key binding surfaces as a tmux error popup (ARCHITECTURE.org), so exit status carries no information here and is not an oracle: =verify-pane-jump.sh= asserts on the active pane id and on captured popup text instead.

* Notes

- ADR-0008 (=docs/adr/0008-own-the-interaction-loop-for-pane-selection.org=) is the decision this binary carries out, and its scope line: owning a keystroke loop is justified for pane selection because tmux has no as-you-type filter over pane titles and =choose-tree -f= drops an empty filter — not as a general licence. It is cited here in prose rather than as a =Links= edge, because atlas edges are node-to-node and the ADR is not a node.
- Build shape: C++20, one translation unit, cmake, the workspace's second non-Rust tool after =sift=. cmake writes the binary into =target/release/= beside the cargo output, so =claude.conf= keeps one path shape for every tool — and so =cargo clean= deletes this binary too.
- The single =switch-client= works because a pane id is a complete tmux target. tmuxlib's =focus_pane()= (=tmuxlib/src/lib.rs:339-351=), which cc-fleet calls from the same position inside a popup, takes the long route instead — resolve the pane's session and window, then =switch-client -t <session>=, =select-window=, =select-pane= — because it starts from a session name.
- The never-write-titles rule and the format-context rule are discharged by grep, not by reading, which is why the source's header comment deliberately does not spell out the command names it forbids: a comment naming them would make the count non-zero and the check worthless.
- Titles reach exactly two places: this popup's own rendering and the =rows= stdout.
- The harness's last three groups run on a nested pair of throwaway servers (=-L pj_verify=, attached from a pane on =-L pj_outer=), because =send-keys= into a pane bypasses the key table — a prefix binding can only be reached through the attached client's terminal.
