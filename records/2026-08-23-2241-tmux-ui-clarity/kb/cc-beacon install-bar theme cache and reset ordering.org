#+TITLE: cc-beacon install-bar theme cache and reset ordering
#+KB_FORMAT: atomic-kb/1

=cc-beacon install-bar= appends the Claude fleet-roster/window glyphs onto the active theme's format strings and caches the pre-append base of THREE options — not the one option =claude.conf='s comment documents. A tmux theme swap must unset all three base keys and then reload exactly once, in that order, or the bar silently keeps rendering the old theme's frozen base (or double-appends). Verified 2026-08-23 against =~/.tmux/tools/cc-beacon/src/main.rs:221-263= and the live server.

* Notes

** The three-key cache

=install_bar()= (=~/.tmux/tools/cc-beacon/src/main.rs:221-243=) loops over three =(option, base_key, segment)= tuples:

| option | cached base key |
|---|---|
| =window-status-format= | =@claude_bar_base_wsf= |
| =window-status-current-format= | =@claude_bar_base_wscf= |
| =status-right= | =@claude_bar_base_sr= |

For each: if the base key is empty it caches *whatever the option currently holds*, then always writes =base + segment=. So reloads never double-append — but the cache is theme-unaware: after a theme swap, options rebuilt from a stale base keep the OLD theme's colors/layout under the glyphs.

=claude.conf='s own comment says only =tmux set -gu @claude_bar_base_wsf= — following it literally leaves =_wscf= and =_sr= stale.

** Reset ordering hazard

Because =install_bar= re-caches only when a base key reads empty, and caches the option's *current* value:

- correct: =tmux set -gu @claude_bar_base_wsf @claude_bar_base_wscf @claude_bar_base_sr= → reload once → fresh theme values cached, glyphs appended once.
- wrong: reload first, then unset → the next reload caches =base+glyph= as the base and double-appends from then on.

** install-bar touches a fourth option family

=apply_border_rule_to_existing_windows()= (=main.rs:249-263=) runs =set-option -wF -t <win> pane-border-status <rule>= per existing window on every =install-bar= — a per-window write independent of the =window-layout-changed= hook in =claude.conf= and of the tmux.conf last-line load-order contract. A theme-swap collision audit must count four option families for cc-beacon, not three.
