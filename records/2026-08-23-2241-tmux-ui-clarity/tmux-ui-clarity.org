*** Resolution

tmux 3.5a. tokyo-night-tmux supplies: status-bar chrome (=status-style=, =status-left/right-length=, =status-left=), the git and path modules, window-naming formats (=window-status-format/-current-format=, =window-status-separator ""=), =pane-border-style=/=pane-active-border-style=, one unconditional =pane-border-status off= write at TPM-load time (=tokyo-night.tmux:27=), and 4 of the 10 interactive-element style options; the other 6 sit at tmux compiled-in defaults, untouched by any config layer (tmux-sensible and tmux-ace-window write no style options). Full mechanics behind the two subtle findings live in the kb atoms [[id:51c9a24b-e07b-479e-8b83-378025e2c549][tokyo-night-tmux widget gating and transparent split]] and [[id:2b82616c-920f-4d22-80f5-b35117637d08][cc-beacon install-bar theme cache and reset ordering]].

**Premise correction (supersedes this session's earlier narration):** only the git and path widgets actually render today. Hostname, battery, music, netspeed, wb-git-status and datetime are wired into the format strings but self-gate on unset =@tokyo-night-tmux_show_*= options and produce empty output. The baseline for t2/t3 treats these six as OFF — the clock needs no removal, only "don't enable it on the new theme".
